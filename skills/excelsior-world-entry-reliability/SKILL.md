# Excelsior World Entry Reliability

Use this below `excelsior-world-slice` and above the normal visual gate. The
MAD, the approved visual target, and the founder's stated release authority
remain canonical.

## Set the entry contract before implementation

For every new world reachable from the wheel, declare:

- the exact route and return route;
- the first usable scene and interaction that counts as arrival;
- the real-phone arrival budget, or a documented reason the product requires a
  different one;
- the fidelity asset that may continue loading after arrival;
- the fallback behavior for a slow or failed optional asset; and
- the current founder authority for preview, merge, non-production, and
  production.

When the founder has already authorized a named action or a standing class of
actions, record the wording and proceed within that unchanged scope. Do not
ask the same approval again. A new project, new member-facing behavior, new
credential, new production target, or scope that exceeds the recorded wording
still needs authority.

## Build entry as a progressive system

Read [references/entry-contract.md](references/entry-contract.md) before
implementing a world entry. Keep the portal animation, route state, and first
usable scene independent from the detailed GLB, texture, or environment
delivery. A detailed asset can improve an already usable world, but cannot
hold the member inside an opaque loader.

## Verify the actual journey

Use [references/entry-contract.md](references/entry-contract.md) to perform
the entry battery. Prove the selected wheel spoke reaches its own world, stays
there, keeps motion alive during staged loading, and returns safely. Treat a
browser-runtime crash as an unrun battery, never as a passing result.

For a hosted handoff, prove the stable project alias is Ready and serves the
same entry bundle that passed locally. Do not hand off an uninspected immutable
deployment URL as the member link.

## Closeout

Record the measured entry result, fallback exercise, exact source commit,
served bundle identity, and release authority in the slice log. Name any
unverified physical-device check directly. The next world starts from this
proven entry pattern, not by copying a stale loader implementation.
