# Corrected-Build Gate Stack

Run in the slice's declared order. The following is the standing visual-world sequence when the amendment does not specify a stricter order.

1. Frozen-pipeline guard
2. Station and ordering invariants
3. Real-input touch census on WebKit iPhone
4. Orb-margin battery with minimum and pose
5. Contrast sweep
6. Plane-separation or z-fighting proof
7. Slice-specific geometry or visual battery
8. Full orbit sweep and gallery
9. Before-and-after crops at every ruled pose
10. Fresh performance measurement in isolation
11. Production build
12. Built-bundle secrets scan
13. Second Member read-only fixture check
14. Demo spine when routing, player, ledger, or progression is in scope
15. Preview bundle-identity proof
16. Device-gate creation for the exact new commit

## Result schema

For each gate record:

- `name`
- `command`
- `commit`
- `started_at`
- `finished_at`
- `exit_code`
- `claimed_floor`
- `measured_result`
- `artifact_paths`
- `rerun_reason`
- `pass`

Do not flatten multiple subsystem assertions into one result. Preserve successful upstream milestones when a downstream wait fails.

## Contamination rules

- Never run two WebKit batteries together.
- Never run two auth-heavy fixtures together.
- Never measure performance while another GPU workload is active.
- Re-run any contaminated result alone before classifying it.
- Re-run all affected gates after a production-code change.

## Visual evidence rules

- Use the same pose, crop, viewport, DPR, fixture, and animation phase for before and after.
- Keep originals beside crops.
- Label images with commit and pose, not subjective verdicts.
- A gallery proves coverage only when its manifest enumerates every required frame.
