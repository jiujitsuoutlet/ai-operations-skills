# Excelsior World Slice

Execute exactly one ruled slice. Treat the current MAD and founder ruling as the specification.

## Workflow

1. Read repository `AGENTS.md`, the Vault rules, canonical `MAD.md`, relevant dated amendments, build log, and prior slice evidence.
2. Start from the founder-named base. Never stack on an unrelated branch. Preserve user changes and confirm the remote branch state before editing.
3. Write a slice contract using [references/slice-contract.md](references/slice-contract.md). Name in-scope surfaces, forbidden systems, gates, evidence, stop point, and debts that remain out of scope.
   When the slice adds or changes a wheel-spoke world entry, also state the
   arrival budget, compact first scene, deferred assets, recovery route, and
   recorded release authority. Use `excelsior-world-entry-reliability` for
   that entry contract and its battery.
4. Capture the governed before state before changing production code. Use the same viewport, account, pose, render state, and production mode required for the after state.
5. Implement the smallest coherent change. Do not absorb adjacent fixes, threshold amendments, optimizations, or held backlog items.
6. Run every mandatory gate sequentially. A skipped, crashed, stale, condition-mismatched, or partially completed battery is not green. Reuse an explicit founder authorization for the same recorded scope rather than asking it again at each mechanical release step.
7. If any mandatory gate fails or a frozen surface must open, stop. Revert experimental attempts that are not part of the ruled slice and report the evidence.
8. Capture after evidence, update the build log and gate ledger, commit, push, update/open the slice PR, serve the commit-embedded production bundle, and stop at the named founder/device gate.

## Laws

- Keep visual taste rulings distinct from technical pass/fail results.
- Preserve pre-existing passes; never manufacture a failure to justify work.
- Preserve failed and rejected evidence. Correct the record append-only.
- Report physical-device performance only from the physical device. Treat desktop WebKit as regression signal.
- Never merge or begin the next slice unless the founder explicitly authorizes it.

Use `$frozen-pipeline-guard`, `$game-world-visual-gate`, `$authenticated-mobile-census`, `$webgl-brightness-guardian`, `$mobile-webgl-device-gate`, or `$persistent-lan-preview` when their specialized proof is required.
