# AI Operations Skills

**Paul Tokgozoglu** · gym owner and business operator

I own and run Jiu Jitsu Outlet, a martial-arts academy business. Through Mat Squad, I also do marketing, CRM, and funnel work for other academies. I am a non-coding operator: I run much of the business through AI agents, mainly Claude Code. When a workflow proves itself in real operations, I turn it into a **skill**. A skill is a written procedure, with its guardrails, that an agent loads and follows the same way every time.

This repository is a cleaned public copy of those skills, 65 in total. The procedures are real and came from live work: HighLevel email campaigns, a lead-nurture agent, Meta ad builds, client platform audits and migrations, and the member app I am building for my academy.

## What these skills have in common

- **A human approves anything that reaches real people or money.** Sends, launches, and publishes happen on the operator's explicit word, and the skill says so step by step.
- **Proof comes from the far end.** An API's "success" does not mean the message was delivered or the record landed. The skills read back the real state before reporting.
- **No invented facts.** Drafts use visible placeholders instead of guessing names, numbers, or dates, and they name the words the model wrote itself.
- **Customer data stays out of chat and logs.** Contact work is count-only or masked.
- **Honest status.** Skills state what is untested, and what was designed but never proven.

## How this public copy was made

- The skills were copied from my private operating-system repo into this fresh repository, without its git history.
- Client names, people's names, account and folder IDs, test logins, internal paths, and business figures were replaced with placeholders or relative wording. A skill changed this way carries a one-line **Portfolio copy** note under its header. Rules and procedures were not rewritten.
- Six skills were held back. One is the unmodified third-party skill above. Five describe a live member app's internals or security setup in too much detail to publish safely.
- No skill script was executed to build this portfolio. "Verification" in the catalog restates each skill's own evidence.

## Using a skill

**Claude Code:** copy a folder from `skills/` into `~/.claude/skills/<name>/` (personal) or `<project>/.claude/skills/<name>/` (project). Claude loads a skill when a request matches its `description`.

**Claude-specific dependencies** (named per skill in the catalog):
- MCP servers: GoHighLevel, Meta Ads, Google Drive connector
- Claude in Chrome, for browser recon
- Claude Code desktop scheduled tasks
- Claude Code preview and browser tools
- Subagents

Several skills also need standard CLIs: `gh`, `vercel`, `wrangler`, the Supabase CLI, Playwright, Python 3, Node.

**Codex:** only the 18 skills listed in Codex's loaded-skill index in my local Codex sessions have any Codex evidence: the 17 Codex-generated skills plus `orchestrate-client-funnel-launch`. No other skill has been tested in Codex.

**claude.ai uploads:** the skill format allows descriptions of up to 1,024 characters. Some descriptions here are longer (see Known issues) and would need trimming before upload.

## Known issues

Left as found so the copies stay faithful, except the first item.

- **Fixed:** three `description` values were wrapped in quotes so their YAML parses. Their text is unchanged. ad-voice failed to parse, and hero-constellation and cosmos-floor-authoring were silently cut off at a ` #`.
- **Descriptions over 1,024 characters:** ghl-nurture-agent, outbound-rollout-safety, jjo-ad-placements, pixel-forensics.
- **funnel-worker is incomplete in the source:** the page templates it imports and a `package.json` with its npm scripts are missing, so the scaffold does not build as-is. Its preflight check also requires you to replace placeholder section names.
- **Internal inconsistencies kept verbatim:** prompt-preflight's step 5.8 conflicts with its own `voice-specs.md`. One older ghl-email-send section predates the resolved finding above it.
- **Some cross-references name skills that are not published here.** These appear as plain text marked "private skill, not published". References to private design docs and notes are marked "not included".
